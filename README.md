# CITL Smart System – Secure v3

نسخة مطورة من نظام الكلية مع الحفاظ على الصفحات والوظائف الحالية، وإضافة طبقة SQL آمنة للإجراءات الحساسة.

## أهم التغييرات

- إزالة مفتاح Supabase `service_role` نهائياً من ملفات المتصفح.
- RLS شامل للملفات الشخصية والأكواد والحجوزات والتواجد والتقارير والإعدادات.
- إشعارات دائمة لكل مستخدم في جدول `notifications` مع `read_at`؛ حالة القراءة لا تضيع عند الخروج والدخول.
- إشعار تلقائي لرئيس القسم والمديرين عند الاعتذار أو الإحلال أو تحويل القاعة.
- تسجيل حساب آمن بكود وصول من خلال تذكرة تسجيل قصيرة العمر ودالة SQL محمية، بدلاً من كشف جدول الأكواد للمتصفح.
- نافذة «متابعة الحضور والانصراف» داخل لوحة إدارة الجداول لإدارة الترم، منتدبي كل ترم، رؤساء الأقسام، QR القاعات وتقارير الحضور والانصراف.
- أسماء المحاضرين تُستخرج تلقائياً من `academic_schedule` كما كُتبت حرفيًا. لا يُستبعد «غير محدد» ولا تُقسم الخانات التي تضم أكثر من اسم بعلامة `/`؛ كل قيمة تبقى اختيارًا واحدًا مقصودًا.
- QR ثابت لكل قاعة طوال الترم، ويُولد فقط للقاعات التي تضم محاضرات لمنتدبين محددين؛ إذا كانت 3 قاعات فقط من أصل 10 بها منتدبون فسيُنشأ 3 رموز فقط.
- صفحة `/attendance/` لمسح QR والتحقق داخل قاعدة البيانات من حساب المنتدب والجدول والقاعة والوقت والتداخل والتكرار.
- التواجد الدوري القديم أصبح للمنتدبين النشطين فقط، ولا يحتسب حضوراً؛ الحضور لا يُحتسب إلا بالـQR.
- نسخ محلية مثبتة من Supabase JS وQRCode وTailwind CSS، وإصلاح مسارات Service Worker وPWA والأرشفة.

## التشغيل المبسط

1. خذ Backup من Supabase.
2. افتح SQL Editor في Supabase وشغّل ملف `SUPABASE-UPDATE.sql` كاملاً مرة واحدة.
3. شغّل ملف جدول الترم في Supabase بعد مراجعته؛ الملف الذي يبدأ بـ`TRUNCATE` يستبدل الجدول الحالي بالكامل.
4. استبدل ملفات الموقع القديمة على GitHub بمحتويات هذه الحزمة، مع بقاء `index.html` في جذر النشر.
5. من `/schedules/` افتح «لوحة التحكم» ثم «متابعة الحضور والانصراف». اختر الترم والمنتدبين من قائمة أعضاء الجدول، اربط الحسابات، حدّد رؤساء الأقسام، زامن الجدول، ثم ولّد QR للقاعات المؤهلة فقط.
6. انتظر نجاح GitHub Pages ثم اختبر `https://aastcitl.me` من نافذة خاصة.

التفاصيل وحالات التوقف موجودة في [DEPLOYMENT.md](DEPLOYMENT.md). لا تُحفظ مفاتيح سرية داخل GitHub أو الحزمة.

## بنية الإضافة

- `supabase/migrations/`: قاعدة البيانات وRLS والتنبيهات.
- `SUPABASE-UPDATE.sql`: ملف التحديث الوحيد المطلوب تشغيله في Supabase.
- `supabase/migrations/`: نسخة مرجعية مطابقة من تحديث قاعدة البيانات وRLS والتنبيهات ودوال RPC.
- `management/`: مكوّن الإدارة المضمّن داخل نافذة الجداول (لا يظهر كرابط مستقل في الهيدر).
- `attendance/`: صفحة المسح من الهاتف.
- `security-core.js`: التحقق من الجلسة والإشعارات والعمليات الحساسة في الصفحات الحالية.
- `cloudflare/`: مرجع اختياري لرؤوس الحماية على النطاق.
- `CNAME`: يحافظ على النطاق `aastcitl.me` عند استبدال ملفات GitHub Pages.
